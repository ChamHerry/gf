## 5. 回滚指南

| 场景 | 回滚动作 | 验证命令 | 风险 |
|---|---|---|---|
| check 命令导致 CLI 无法启动 | 移除 `gfcmd.go` 中 `cmd.Check` 行 | `cd cmd/gf && go run . -h` | 低 |
| 规则引擎有严重 bug | 删除 `cmd/gf/internal/cmd/check/` 和 `cmd_check.go`；移除 `gfcmd.go` 注册 | `cd cmd/gf && go build ./...` | 低 |
| 误报过多 | 使用 `--skip rule-id` 跳过规则或修改规则 severity 为 info | `gf check --skip DIR-005` | 低 |
| 性能问题 | 限制扫描范围或减少规则数量 | `gf check -p ./api --skip CODE-*` | 低 |

## 6. 维护指南

### 6.1 常用操作

| 操作 | 命令/入口 | 说明 |
|---|---|---|
| 检查当前项目 | `gf check` | 检查当前工作目录的 GoFrame 项目 |
| 检查指定路径 | `gf check -p /path/to/project` | 检查指定目录的项目 |
| 严格模式 | `gf check -s` | 将 warning 升级为 error |
| 跳过规则 | `gf check --skip DIR-005,CODE-META-005` | 跳过指定规则 ID |
| JSON 输出 | `gf check --json` | 输出 JSON 格式结果（用于 CI） |
| 配置忽略规则 | 在 `hack/config.yaml` 中设置 `gfcli.check.skip` | 持久化跳过规则 |

### 6.2 配置说明

| 配置 | 推荐值 | 注意事项 |
|---|---|---|
| `gfcli.check.skip` | `[]` (默认空) | 配置跳过的规则 ID 列表 |
| `gfcli.check.strict` | `false` | 是否启用严格模式 |

`hack/config.yaml` 示例：

```yaml
gfcli:
  check:
    skip:
      - "DIR-008"    # 跳过 resource/ 目录检查
      - "CODE-META-005"  # 跳过 summary 标签检查
    strict: false
```

### 6.3 日志与排查

| 场景 | 查看位置 | 判断方法 |
|---|---|---|
| 检查结果异常 | `gf check -p <path>` 输出 | 查看 violation 列表和 rule ID |
| 规则未生效 | `gf check -p <path> --json` | 检查 JSON 输出中是否包含预期规则 |
| 性能问题 | `gf check -p <path> -d` (debug 模式) | 查看扫描和解析耗时 |
| 误报排查 | 查看 rule ID 对应的规则文件 | `cmd/gf/internal/cmd/check/rules_*.go` |

## 7. 已知限制

| 限制 | 影响 | 后续建议 |
|---|---|---|
| 不支持自定义规则插件 | 用户无法添加自己的检查规则 | NEXT-004: 支持自定义规则 |
| mono-repo 仅做基本检查 | 无法深度验证 mono-repo 的所有规范 | NEXT-006: 增强 mono-repo 支持 |
| 不检查 protobuf/gRPC 代码 | gRPC 项目规范无法验证 | NEXT-005: 添加 gRPC 规范检查 |
| 不集成 golangci-lint | 无法复用 golangci-lint 的规则生态 | NEXT-002: golangci-lint 插件集成 |
| AST 解析不包含类型信息 | 无法检测接口实现等需要类型信息的规则 | NEXT-001: 可选引入 go/analysis |
| 不支持 SARIF 输出 | 无法直接集成 GitHub Actions Code Scanning | NEXT-007: 添加 SARIF 格式 |
