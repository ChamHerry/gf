# Elasticsearch/OpenSearch 搜索引擎支持方案 — 使用说明

> 适用位置：`docs/todo/Elasticsearch-OpenSearch搜索引擎支持方案/`  
> 核心用途：让后续 LLM 或工程师能基于当前调研证据、调用链证据和任务队列持续推进实现。  
> 当前状态：本目录是实施方案与恢复控制台，不包含代码实现。

---

## 1. 恢复入口

每次继续本功能前，按顺序读取：

1. `README.md#0-LLM-STATE每轮实施前必须读取`
2. `01-实施计划.md#6-LLM任务队列`
3. `02-实施状态与验证.md#3-执行日志`

若用户要求直接实现，先确认 OpenSpec 状态。当前仓库存在未归档 `openspec/changes/*` 目录；如果用户未指定新变更，进入代码实现前应先用 `/opsx:explore` / `/opsx:propose` 明确本功能归属，避免绕过项目 SDD 规则。

功能状态只使用：


```text
todo | in_progress | blocked | done | skipped
```

```text

```

```text

```

## 3. 执行协议

### 3.1 实施前

1. 重新读取 `README.md` 的 `LLM-STATE`。
2. 重新校准目标分支、`go.mod` Go 版本、GitNexus 索引新鲜度和相关源码行号。
3. 选择第一个满足依赖的 `T-###`。
4. 若实现代码，必须先有 OpenSpec 变更并更新 `tasks.md`。
5. 若修改代码，必须添加或更新单元测试。

### 3.2 实施中

每个任务必须遵循：

```text
读取任务 -> 校准源码和调用链 -> 限定文件范围 -> 最小切片实现 -> 运行验证 -> 写执行日志 -> 更新状态
```

禁止：

- 将 ES/OpenSearch 放入 `database/gdb` 或 `contrib/drivers/*`。
- 在 root `go.mod` 引入 `github.com/elastic/go-elasticsearch` 或 `github.com/opensearch-project/opensearch-go`。
- 只按 HTTP status 判断 Search/Bulk 成功。
- 在 root API 暴露官方 typed API 或 adapter 私有类型。
- 直接写 raw string 作为枚举语义；实现时必须用 Go named type + const。

### 3.3 实施后

每轮结束前更新：

1. `README.md` 的 `LLM-STATE`。
2. `01-实施计划.md` 的任务状态和证据。
3. `02-实施状态与验证.md` 的命令、结果、阻塞和 VERDICT。

---

## 4. 证据规范

完成状态必须绑定至少一种证据：

| 类型 | 示例 |
|---|---|
| 源码行号 | `database/gdb/gdb.go:905` |
| GitNexus | `context(RegisterAdapterFunc)` |
| DeepWiki | `elastic/go-elasticsearch Architecture` |
| 官方文档 | `https://www.elastic.co/docs/reference/elasticsearch/clients/go/getting-started` |
| GitHub 参考 | `elastic/go-elasticsearch` / `opensearch-project/opensearch-go` |
| 命令 | `go test ./database/gsearch/... -count=1 -race` |

不要写：

```text
Status: done
Evidence: 已完成
```

应该写：

```text
Status: done
Evidence: `database/gsearch/gsearch.go` 新增 typed registry；`go test ./database/gsearch/... -count=1 -race` PASS。
```

## 5. 实施前检查清单

- [ ] 是否先处理 OpenSpec 归属？
- [ ] GitNexus `gf` 索引是否仍匹配当前 HEAD？
- [ ] `go.mod` 是否仍为 Go 1.23+？
- [ ] 是否确认 Elastic v9 的 Go 版本边界？
- [ ] 是否确认 OpenSearch client 当前稳定版本与兼容矩阵？
- [ ] 是否确认 `database/gdb` 不在修改范围？
- [ ] 是否确认 root API 不引入外部 SDK 类型？
- [ ] 是否为每个代码任务准备了单元测试？

---

## 6. 实施后检查清单

- [ ] 所有 required 任务为 `done` 或有明确 `skipped` 理由。
- [ ] Root `go.mod` 没有新增 ES/OpenSearch SDK。
- [ ] 两个 contrib 模块均有独立 `go.mod`、README 双语说明和测试。
- [ ] Missing adapter、product mismatch、bulk per-item error、search partial failure 均有测试。
- [ ] `make tidy` 和相关模块测试已运行。
- [ ] `/gf-review` 已完成并记录问题处理。
