## 1. 实施结论

当前 GoFrame 支持的数据库驱动集中在 `contrib/drivers/*`，通过 `gdb.Register` 注册到 SQL ORM；Redis 作为 NoSQL 能力则走 `database/gredis` root 抽象和 `contrib/nosql/redis` adapter。Elasticsearch/OpenSearch 的语义是搜索/文档引擎，底层虽然是 HTTP JSON REST，但不是 `database/sql`、没有 SQL 事务、没有表字段元数据，也不适合参与 DAO 生成。

推荐实现路径是新增 `database/gsearch` root 抽象，配置节点使用 `search`，真实 SDK 依赖分别放入 `contrib/nosql/elasticsearch` 与 `contrib/nosql/opensearch`。两个 contrib 模块共用 root 接口，但实现完全分离，以处理 Elastic Cloud/API key/service token、OpenSearch AWS SigV4、产品/version 检查、插件能力和 typed API 演进差异。

最小安全切片是先落 root `gsearch` 的配置、按类型注册、fake adapter 和基础请求/响应模型，再并行实现两个 contrib adapter。首版只覆盖通用基础操作和 raw escape hatch，不构建完整 DSL，不把官方 typed API 暴露到 root。

LLM 当前已完成全部 required 任务：T-001~T-009 均有验证证据。Elasticsearch adapter 采用官方 `go-elasticsearch/v8`，依赖只存在于 `contrib/nosql/elasticsearch`；OpenSearch adapter 采用官方 `opensearch-go/v3 v3.1.0`，依赖只存在于 `contrib/nosql/opensearch`；两个 contrib 模块的双语 README 已补齐，最终测试、tidy、lint、OpenSpec validate、GF Review 和 Docker 真实服务 E2E 均通过。

## 4. 目标方案

### 4.1 目标链路

```text
import _ "github.com/gogf/gf/contrib/nosql/elasticsearch/v2"
import _ "github.com/gogf/gf/contrib/nosql/opensearch/v2"

g.Search("default")
  -> gins.Search("default")
  -> Config().Get(ctx, "search")
  -> gsearch.ConfigFromMap(configMap["default"])
  -> gsearch.Instance("default")
  -> gsearch.New(config)
  -> adapterFactoryMap[config.Type](config)
  -> contrib adapter maps config to official client config
  -> official client performs REST request
  -> adapter maps response/error to gsearch response/error
```

### 4.2 设计决策

| D-ID | 决策 | 理由 | 拒绝方案 | 影响任务 |
|---|---|---|---|---|
| D-001 | 不实现为 `gdb.Driver` | `gdb` 是 SQL/ORM/`database/sql` 模型 | 在 `contrib/drivers` 新增 ES driver | T-002 |
| D-002 | 新增 `database/gsearch` root 抽象 | 符合 GoFrame root 轻依赖约束 | 直接让用户使用官方 SDK | T-002 |
| D-003 | adapter registry 按 `EngineType` 分发 | 同一进程可同时导入 ES/OpenSearch | Redis 当前单默认 adapter | T-002 |
| D-004 | 配置节点命名为 `search` | 避免污染 `database` 配置和 DAO 语义 | 复用 `database.type=elasticsearch` | T-004 |
| D-005 | 两个 contrib 模块分开实现 | 官方兼容、认证、插件、typed API 分叉 | 单 adapter 内部 switch | T-005,T-006 |
| D-006 | root API 只暴露基础操作 + raw `Perform` + `Client()` | 保持稳定，支持未覆盖端点 | root 暴露 generated typed API | T-003 |
| D-007 | Search/Bulk 响应保留 partial/per-item/shard 信息 | 搜索成功语义不等于 HTTP 2xx | 只返回 `gvar.Var` | T-003 |
| D-008 | 真实服务集成测试使用 env/docker opt-in | 本地和 CI 不一定有 ES/OpenSearch | 默认强依赖外部服务 | T-008 |
| D-009 | 文档必须声明版本、许可、专利边界 | 防止用户误解兼容性和授权 | 只写代码示例 | T-007 |

| 兼容项 | 策略 | 验证方式 | 覆盖任务 |
|---|---|---|---|
| 默认行为 | 新增包和 facade，不改变 `gdb`/`gredis` 行为 | 现有相关测试通过 | T-008 |
| Root 依赖 | root 不新增官方 SDK | `go.mod` diff | T-002 |

1. 完成 OpenSpec review。
2. 合并 root `gsearch` 和 facade。
3. 发布两个 contrib module。
4. 更新官方文档和示例。
5. 在 release note 写清版本兼容和非目标。

### 10.2 回滚方案

| 场景 | 回滚方式 | 验证 |
|---|---|---|
| root API review 不通过 | 删除 `database/gsearch` 和 facade，保留方案文档 | `go test ./...` targeted |
| Elastic SDK Go 版本不兼容 | 降级到 v8 或推迟 ES adapter | `cd contrib/nosql/elasticsearch && go test ./...` |
| OpenSearch SDK API 变化 | 锁定稳定 v4 或调整 adapter | `cd contrib/nosql/opensearch && go test ./...` |
| facade 引发争议 | 仅保留 `gsearch.Instance` | `go test ./database/gsearch/...` |
